2. No CLI runtime evidence. The plan's CLI smoke matrix (`sync <dir> --once`, `--watch --once`, `--source`, `--interval`, graph output) has no captured output; only `qbrain_tests.exe` ran. Assertion 2's CLI half rests on code inspection of the 2-line flag mapping.

**P2**

1. Ledger timing (plan-audit P2 #1): no rows beyond the plan's eight are claimed — exactly `forget_fact, recall, resolve_slugs, retry_job, sources_remove, sources_status, sync_brain, traverse_graph` carry N13 attribution. But they read **implemented** and `OPS-PARITY-LEDGER.md:127` asserts "D1–D25 usable gates: met (N0–N11 + N12–N13 extensions)" while the outcome gate was pending; the N13 note (`:122`) lacks the "plan audit PASS + outcome hard audit PASS" wording that N12 (`:121`) carries. Retrospective sequencing, acknowledged in the plan; add the N12-style wording now.
2. `recall` conservative semantics (plan-audit P2 #2) now concrete and consistent with the ledger: `handlers.cpp:1252-1262` aliases `search`, defaults `mode=conservative`, maps `q`→`query`; `:261` skips query embedding under that mode; `hybrid.cpp:148-150` sets `use_vec=false`, `cand=limit*2`. So conservative = lexical-only, no provider/embedding call. Untested without an explicit `no_vector` argument.
3. Sync-state medium (plan-audit P2 #3): JSON file at `%LOCALAPPDATA%\Qbrain\sync-state\<hash>.json`, one per brain/source/root scope. Concurrency is unguarded — `load_state`/`save_state` (`live_sync.cpp:29-51`) do full read-modify-write with no lock, so two concurrent syncs of the same scope lose entries (last writer wins); corrupt JSON is swallowed (`:41-43`) and degrades to re-import, not data loss. Scope key uses `brain_id`, not the db path, so distinct DBs opened via `open_at` under one brain id share state; the test sidesteps this with distinct ids. Test-written state files also land in the real `sync-state` directory and are not cleaned (only the temp root is removed).
4. Test coverage narrower than assertion text, each structurally guaranteed by code read: chunks/tags orphan-absence after force removal (cascade + pragma), per-status retry rejection and unknown id (single WHERE clause), `sources_status` deleted-page exclusion and `last_updated`, imported-link `source_id`, real symlink escape (only `..` escape is exercised), and no post-read-op snapshot equality for assertion 12.
5. Evidence hygiene: `n13-evidence/CLAUDE-N13-HARD-AUDIT-RESPONSE.txt` is truncated mid-table at row A1 and self-reports that the plan audit's full text was not re-read — it must not be mistaken for the outcome audit. `VERIFY-REPORT.md` was produced with `-SkipBuild`, so "Canonical build exit code: 0" is inherited from the reused `BUILD-OUTPUT.txt` (disclosed in its Commands block; the embedded test run there timestamps 09:18:02Z versus 09:45:17Z in `TEST-OUTPUT.txt`).
