Coordination items found by this slice (for the parent):
  1. n32 "synchronous command execution functions are not allowed in
     pipeline mode" (B's PG-mode probe attribution: A backend call
     sequence) is NOT a PgBackend defect: pg_backend.cpp contains zero
     PQenterPipelineMode/PQsendQuery/PQsetnonblocking calls. Root cause:
     tests/test_n32.cpp:170 PageReadObserver(brain.db().handle()) -- in PG
     mode Database::handle() (database.cpp, frozen for A) performs a
     static_cast<SqliteBackend*> on a PgBackend and returns the PGconn* as
     an sqlite3*; sqlite3_set_authorizer then writes into the PGconn struct
     and corrupts libpq state (the "pipeline mode" error is the corrupted
     readback). Suggested one-line parent fix: guard handle() on
     backend_kind() == sqlite (return nullptr otherwise); C then guards the
     observer on handle() != nullptr.
  2. B's "fts_search throws" CLI observation was A's real bug -- the
     no-source_id path bound 3 params against a 2-parameter statement
     (08P01). Fixed and covered by H10 (both filter paths); B's smoke
     should be re-run after pulling the current pg_backend.cpp.
  3. C's test_n38.cpp G1 expects "1:alpha;2:gamma;" -- PG identity
     sequences are not transactional; the rolled-back beta permanently
     consumes id 2 (B's probe: expected value "1:alpha;3:gamma;"). C-side
     expectation update.
