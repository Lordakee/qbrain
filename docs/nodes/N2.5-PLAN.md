**Status**: done (plan PASS + outcome PASS 2026-07-28)

**Outcome audit**: docs/nodes/N2.5-HARD-AUDIT.md  

## Goal

Source registry and remote source_id authorization:

1. Validate source_id before any registry write
2. List sources (Read) and add sources (local-only Write)
3. Remote MCP always enforces allowlist on every remote write that accepts source_id: put_page, capture, and any other Write op with source_id arg
4. sources_add is **localOnly**: remote MCP callers cannot sources_add even with allow-write (prevents remote registration of non-allowlisted ids). Local CLI may sources_add any valid id
5. sources_add (local) is still Write under default-deny when exposed via MCP without localOnly bypass — if registered localOnly, remote always denied

## source_id rules (normative)

Valid only if all hold:

1. Length 1..64 inclusive (0 and 65+ rejected)
2. Matches `^[A-Za-z0-9_-]+$`
3. Lowercase not in Win32 reserved set: CON, PRN, AUX, NUL, COM1-COM9, LPT1-LPT9
4. Uniqueness and allowlist membership are case-insensitive; store canonical lowercase

## Ledger rows

| op | scope | notes |
|----|-------|-------|
| sources_list | Read | includes default after init; remote OK |
| sources_add | Write + localOnly | remote always denied; local CLI OK with validation |
| ensure_source | internal | same validation |
| remote allowlist | behavior | ctx.remote => source_id in {default} ∪ mcp.allowed_sources for put_page, capture, and all Write ops taking source_id |

## Deliverables

- sources table + ensure_source / sources_add / sources_list
- Config mcp.allowed_sources comma-separated; empty => remote only default
- Remote put_page and capture: disallowed source_id fail closed
- Remote sources_add: always fail closed (localOnly)
- Local CLI: sources_add and non-default source_id without allowlist OK if valid

## Tests

- valid/invalid ids including CON, 65-char
- sources_list has default
- local sources_add team_a then list contains team_a
- MCP remote sources_add denied even with allow-write
- MCP sources_add without allow-write denied (if not localOnly short-circuit, still fail)
- remote empty allowlist: put_page and capture source_id=other denied; default ok
- remote allowlist team_a: team_a ok; other denied; Team_A == team_a
- local CLI source_id=team_b without allowlist entry succeeds

## Acceptance assertions (falsifiable)

1. sources_list after open/init includes default
2. sources_add of CON, a/b, or 65-char id fails; no new row
3. Remote MCP sources_add (with or without allow-write) is denied; no new row
4. Local sources_add of team_a succeeds; sources_list includes team_a
5. Remote + empty allowlist: put_page source_id=other fails closed; default allowed
6. Remote + empty allowlist: capture source_id=other fails closed; default allowed
7. Remote + mcp.allowed_sources=team_a: put_page source_id=team_a allowed; other rejected
8. Team_A and team_a treated as same id for allowlist/registry
9. Local non-remote put/capture with valid source_id=team_b succeeds without mcp.allowed_sources entry

## Rollback

Clear mcp.allowed_sources; use default only.

## Security notes

- sources_add is Write and localOnly: remote cannot register sources
- Remote allowlist always enforced on put_page and capture when ctx.remote
- Local paths unbound by allowlist; still bound by validation rules
- Source ids are not credentials
- Length, reserved names, case-insensitive identity required
